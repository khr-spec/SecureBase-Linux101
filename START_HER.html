SecureBase
Deployment & kontrol

Den manuelle SecureBase-server omsat til en modulopdelt og genkørbar Bash-deployment. Pakken er nu testet end-to-end på en frisk Ubuntu Server 26.04.1 VM.

Verificeret 17. september 2026. Preflight, fresh deployment, statisk Netplan, SSH public-key login, begrænset sudo, UFW, monitoring og en gentagen deployment blev afprøvet. Anden kørsel rapporterede 0 ændrede administrerede filer.
OVERBLIK

Én konfiguration. Tydeligt ansvar.

config.env + public key→setup.sh + moduler→Ubuntu + healthcheck

Scripts ændrer ikke VirtualBox-portforwarding. Bootstrap-kontoen beholder fuld sudo; secureadmin får kun tre specifikke driftskommandoer. Den private SSH-nøgle bliver på Windows.

01 / START HER

Kontrollér pakken

Efter udpakning på Ubuntu:

cd ~/securebase-deployment
sha256sum -c SHA256SUMS
sudo bash ./setup.sh --check

--check validerer forudsætninger uden at ændre systemkonfigurationen. Det er preflight, ikke en fuld dry-run.

Den verificerede fresh-install test brugte en lokal bootstrap-konto og overførte arkivet via VirtualBox NAT. Se README og VM-teststatus.

Tilpas altid config.env til miljøet før --apply. Den testede Netplan-sti gælder single-NIC VirtualBox NAT.

03 / DEPLOY

Kontrolleret first-run

sudo bash ./setup.sh --apply --console-confirmed

Public key installeres før SSH-hærdningen. Ved sikkerhedsstop testes en ny key-only SSH-session fra Windows; først derefter bekræftes KEY-OK. Netplan køres til sidst og skal bekræftes fra konsollen ved NETWORK_APPLY="try".

VirtualBox er separat: host-forwarden 127.0.0.1:2222 → 10.0.2.15:22 konfigureres på værten. Ubuntu-SSH lytter fortsat på guest-port 22.
04 / HEALTHCHECK

Verificeret resultat

[OK]   19 kontroller bestået
[WARN] 1 observationsadvarsel
[FAIL] 0

Den observerede WARN skyldtes, at who/utmp ikke viste sessionerne, mens systemd-logind gjorde. Den blev derfor dokumenteret som WARN og ikke skjult som PASS.

Kør igen med sudo bash ./healthcheck.sh eller den installerede /usr/local/sbin/securebase-healthcheck.

05 / IDEMPOTENS

Anden kørsel er verificeret

Deploymentet blev kørt igen med samme ønskede tilstand. Brugere og grupper blev bevaret, public key, SSH, sudoers, UFW, monitor, cron, logrotate og Netplan var allerede korrekte.

[OK] Ændrede administrerede filer i denne kørsel: 0

Det er det centrale VM-bevis på genkørbarhed. Driftslogs og pakkearkiver kan naturligt ændre sig uden at bryde idempotens.

06 / SLUTKONTROL

Fresh VM → fungerende administrationsvej

Efter deployment og idempotens-test blev en ny Windows SSH-session etableret som secureadmin@securebase-server. sudo -l viste alene de tre afgrænsede SSH-driftskommandoer; den brede sudo-gruppe var ikke nødvendig for den daglige administrator.
